## 首个工具的任务边界

首个候选工具 `analyze_causal_impact` 接收新的数值时间序列、前期和干预后区间，以及原包支持的部分模型选项；调用导出的 `CausalImpact::CausalImpact()`；返回结构化汇总、逐点和累计结果序列，以及绘图文件。

这是一个可单独使用的任务。数据检查、干预区间解析、模型构建、后验推断、效果计算、结果汇总和绘图暂时作为一次分析调用中的内部步骤。只有后续使用证据表明有独立调用需求时，才考虑拆分工具；不因上游代码把实现拆在多个文件中就机械地暴露内部函数。

## 源码对应关系与取舍

| 候选能力 | 源码对应 | 决策 |
|---|---|---|
| 分析新的干预 | `R/impact_analysis.R` 中导出的 `CausalImpact()`；模型与推断实现位于 `R/impact_model.R`、`R/impact_inference.R` | 选为首个 MCP 工具，直接调用原包完成分析。 |
| 绘制影响图 | `R/impact_plot.R` 中的 S3 方法 `plot.CausalImpact()` | 首轮保留在分析调用中；若要独立提供，需要持久化并传递结果对象，还需有后续独立使用场景。 |
| 生成摘要和报告 | `R/impact_analysis.R` 中的 S3 方法 `summary.CausalImpact()`、`print.CausalImpact()` | 与分析结果一并返回，首轮不拆成独立工具。 |
| 转换自定义模型对象 | 导出的泛型 `as.CausalImpact()`；默认方法在模型对象未提供转换器时会报错 | 暂不纳入。尚未找到可适用于任意客户端模型对象的通用转换方式。 |
| 分析预先拟合的 BSTS 模型 | `R/impact_analysis.R` 中 `CausalImpact(bsts.model=..., post.period.response=...)` 分支 | 暂不纳入首个任务；R 模型对象的输入输出和新用户调用约定需要单独设计。 |

## 可追溯的初始示例

官方 vignette 和 `tests/CausalImpact_import_test.R` 使用同一种确定性数据生成流程：调用 `set.seed(1)`，生成 100 个时间点的 AR(1) 控制序列，响应序列为 `1.2*x1 + noise`，并在观测点 71 至 100 加入 +10 的变化。测试检查包调用是否返回 `CausalImpact` 对象；vignette 报告平均估计效果约为 11，95% 区间约为 [9.8, 11]。该示例可作为有源码依据的冒烟和参考用例，但不能证明一般情况下区间覆盖率或因果假设成立。

源码中与输入有关的约束包括：数值时间序列、第一列为响应序列、后续列为协变量、协变量不能缺失、公开输入格式至少四行、日期索引区间需要时间类型一致，以及具体模型的其他限制。封装应保留原包的校验行为，避免静默改变输入。
